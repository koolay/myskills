# ko-dx-rca

从症状追踪到证据支持的因果链，搜索同类路径，并区分局部修复与能防止同类问题的修复。

执行规则以 [SKILL.md](./SKILL.md) 为准；安装方法见[项目 README](../README#安装与使用)。

## 适用场景

报告 bug、询问行为原因、要求 5-Why 分析，或验证已有修复是否真正处理了根因。

## 使用示例

```text
使用 ko-dx-rca 分析为什么保存后页面显示旧数据。入口在 src/editor，重点检查保存、重试和历史回放路径，并判断现有补丁是否只修了一个场景。
```

## 输入与产出

- **输入：** 症状或待检查补丁；可选的复现步骤、错误、相关文件、近期变更和前后端或基础设施范围。
- **产出：** RCA 报告：结论与置信度、症状、带证据等级标签的因果链、逃逸原因、Point / Class / Hybrid 与 Eliminate / Detect / Mitigate / Configure 修复分类、已排除的替代解释、同类路径、证据闭环和剩余风险。

## 执行流程

1. 定位每个独立症状及其数据流，并区分“被观测系统的事实”和“观测或报告环节的缺陷”。
2. 逐步回答 Why，每步标注证据等级（observed / code / doc / inferred）；多个必要条件并列展开，不强凑五层。
3. 用反事实检验确认根因，并追问逃逸原因（为什么没被测试或告警拦住）。
4. 提炼失败模式与应守住的不变量，在代码、运行时数据和部署配置中实际搜索同类路径。
5. 给出修复建议，标明影响面和修复层，列出至少两个已排除或仍未排除的替代解释，并让结论强度不超过最弱一环。

## 边界与前提

每个因果判断都要有源码、配置或运行时证据，推测和仅来自文档的环节要在结论中标明。被分析系统自身的诊断输出不算独立证据。分析只使用只读命令；找不到相关代码、数据或症状无法定位时先补充上下文。分析请求提供报告和修复建议；实施修复仍需对应授权。
