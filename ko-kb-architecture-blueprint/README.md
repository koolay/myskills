# ko-kb-architecture-blueprint

记录当前真正实现的架构、关键流程与扩展位置，为继续开发提供可追溯的地图。

执行规则以 [SKILL.md](./SKILL.md) 为准；安装方法见[项目 README](../README#安装与使用)。

## 适用场景

了解现有仓库整体架构，生成架构蓝图，或确定新功能应该放在哪里、遵循哪些现有契约。

## 使用示例

```text
使用 ko-kb-architecture-blueprint 为当前仓库生成架构蓝图，面向新增功能的开发者。追踪一个真实请求，标出主要模块、契约、数据归属和扩展范例。
```

## 输入与产出

- **输入：** 当前或指定仓库；可选读者、子系统范围、文档深度和输出路径。
- **产出：** 有源码引用的系统地图、关键流程与契约、实现模式、扩展指南和未知项；存在 docs/ 时默认写入 docs/architecture-blueprint.md。

## 执行流程

1. 检查项目指令、文件树、入口、配置及代表性测试。
2. 追踪真实运行流程；文档或库仓库则追踪产物发现和使用流程。
3. 区分已观察事实、文档意图、推断和未知，形成模块与边界地图。
4. 给出有现有实现范例的扩展建议，复查路径、关系和检查范围。

## 边界与前提

描述现状，不把熟悉的架构模式强加到仓库。新架构或重大技术决策应使用 ko-sd-architect。没有运行时的文档仓库不会被虚构为服务系统。
