# ko-sd-architect

围绕领域结果、契约和恢复能力选择最小可交付架构，并建立可以验证的验收证据。

执行规则以 [SKILL.md](./SKILL.md) 为准；安装方法见[项目 README](../README#安装与使用)。

## 适用场景

技术选型、跨模块契约、数据归属、破坏性迁移，或 AI 实施边界需要明确决策。

## 使用示例

```text
使用 ko-sd-architect 评估订单事件是否需要引入消息队列。读取现有重试与数据契约，对比沿用现状和最小改造，给出故障恢复、验收检查与重新评估条件。
```

## 输入与产出

- **输入：** 用户目标及待决策问题、代码与领域证据、预算 / 兼容性 / 安全 / 运营约束、授权范围。
- **产出：** 推荐方案、事实与假设、取舍、契约与恢复边界、已执行 / 计划 / 阻塞检查；必要时给出实现切片或架构文档。

## 执行流程

1. 明确结果、硬约束、重要未知和可观察验收条件。
2. 追踪代表性流程、数据所有权、受影响契约、失败检测和恢复；需要迁移时加载迁移规则。
3. 评估现状与最小改变，用有界实验解决决定方案的未知，推荐可验证的方案。
4. 需要实施时确定最少切片、共享契约、文件归属、顺序和集成验证点。

## 边界与前提

默认给出建议，执行只限已有授权。已确定契约下的局部改动或单个 bug 不需要架构流程。正式架构文档要应用专门输出规范；无法满足硬约束时保留约束并报告冲突。
