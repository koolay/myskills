# ko-sd-project-harness

为空 startup 项目建立可导航、可检查、可恢复的工程基线；对已有代码库先形成增量改进计划。

执行规则以 [SKILL.md](./SKILL.md) 为准；安装方法见[项目 README](../README#安装与使用)。

## 适用场景

初始化空仓库，创建 agent 指令和项目布局，或改进现有项目的 AI-native 工程结构与反馈回路。

## 使用示例

```text
使用 ko-sd-project-harness 评估这个已有仓库的 AI-native 工程基础。先提供增量计划，列出证据、最小改动和验收命令，不移动文件或修改部署。
```

## 输入与产出

- **输入：** 目标仓库和请求；可选产品目标、技术栈、部署环境、数据与安全约束及可修改范围。
- **产出：** 空仓库：最小可执行布局、agent contract 和可用 quickstart。已有仓库：带验收门槛、迁移风险和实施顺序的增量计划。

## 执行流程

1. 检查 git 状态和已有指令，判定空仓库或非空仓库。
2. 盘点真实产品、运行时、命令、CI、边界、可观测性及恢复方式。
3. 空仓库按已知技术栈初始化；已有仓库按可读性、边界、反馈、恢复和维护形成计划。
4. 验证真实命令与链接，报告运行过和未运行的检查，交接下一个最小切片。

## 边界与前提

默认只做仓库本地结构和文档。未知技术栈时只创建安全的技术中立文件；不虚构应用、CI 通过或集成。已有仓库的结构迁移先取得计划授权。不自动部署、迁移数据或轮换凭据。
