# AI Agent Relationship Design

**Goal:** 让 AI Agent 在持续协作中延续用户目标，提供可控制、可纠正的记忆和行动体验。

**Use when:** 设计或评审长期使用的 Agent、助手、AI 工作台；用户反复交代背景；需要设计记忆管理、授权范围、共同规划或错误恢复。

**Do not use when:** 一次性问答、静态网站、普通视觉润色、仅后端框架选型。不要因为产品带有 AI 就套用长期关系设计。

## Inputs

- **任务与用户：** 产品或流程、用户目标、使用频率、预期协作周期。
- **现有证据：** 可选界面、用户反馈、任务记录、已知限制；先阅读已有资料。
- **能力与边界：** 记忆来源和可用工具、现有授权、敏感数据、可撤销与不可撤销动作。
- **交付范围：** 默认给设计建议；仅在用户要求时实现界面或修改代码。

## Execution

### Phase 1: 找到持续协作的价值

1. 明确一个用户目标，以及首次使用、再次回来、目标变化时应发生的行为。区分事实与设计假设。
2. 找出重复解释、丢失进度或错误沿用偏好的具体成本；如果持续记忆没有实际价值，采用会话内上下文即可。
3. 只询问影响数据使用、动作权限或核心流程的关键缺口；其余可逆设计选择给出标明假设的最小方案。

### Phase 2: 定义记忆契约

1. 区分当前任务状态、用户明确提供的偏好、行为推断。推断不得冒充用户确认的事实，情绪判断只作待确认提示。
2. 只保留完成目标所需信息。为每类持久记忆写明用途、来源、作用范围、更新时间、失效或删除条件；不默认保存全部聊天或敏感信息。
3. 当前明确指令优先于旧偏好；过期或矛盾信息需纠正、忽略或向用户确认。暂停、取消和完成的任务不得自动恢复执行。
4. 设计查看、更正、删除、关闭记忆的入口。说明删除覆盖原记录、摘要和派生检索数据的范围，以及备份保留等限制；无法即时完成时显示真实状态，并停止后续读取待删除内容。
5. 说明跨会话或跨设备实际能恢复什么。团队产品需定义个人、项目和团队可见范围；没有存储或隔离能力时标为待实现，不声称已经记住。

### Phase 3: 将信任转化为可控授权

为实际动作建立下表；沿用用户已经给出的有效授权，不重复确认。

| 动作与影响 | 现有授权与有效范围 | 交互方式 | 结果证据与恢复 |
| --- | --- | --- | --- |
| 具体动作、外部副作用、是否可撤销 | 对象、条件、限额、期限 | 建议 / 预览确认 / 范围内执行 | 状态、停止、撤销或补救 |

1. 初次或高影响决策展示依据、来源、主要取舍和不确定性；常规操作可压缩展示，保留按需查看入口。展示简明决策说明，不要求暴露内部思维链。
2. 自主执行仅限明确授权的动作类别与条件；成功次数、熟悉程度或模型置信度不能扩大权限。用户可随时收紧或撤销授权。
3. 不编造精确置信度。外部动作结果未知时显示“待核实”，先核实结果，再决定是否重试，避免重复副作用。
4. 出错时说明实际影响和下一步；可撤销则提供撤销，不可撤销则说明补救与人工接管。撤回权限应阻止后续动作，并报告已开始动作是否还能停止。

### Phase 4: 设计共同规划与交互状态

1. 用用户目标、完成条件、当前进度、下一步和阻塞点组成最小共享计划；用户能修改、暂停、继续或取消。Agent 的建议不能自行替换目标。
2. 用户返回时简要恢复已完成、待处理和待确认内容；目标或约束变化时更新受影响步骤，不重复整个问卷。
3. 定义建议、待授权、执行中、完成、失败、结果未知、已暂停 / 取消的可见状态；重要变更说明原因，不暗示尚未完成的动作成功。
4. 主动建议对应当前目标，并可忽略或关闭；自适应界面保留核心入口和用户选择，避免不断移动控件。
5. 按具体问题选择记忆摘要、动作预览、进度卡或恢复入口；不默认建设完整仪表盘。控制与状态支持键盘和辅助技术，不能仅依赖颜色或 hover。

### Phase 5: 验证连续性与实际收益

1. 选择少量指标并定义分母、观察周期和数据来源，例如返回任务的背景重复次数、任务成功率、被纠正的记忆比例、越权动作数、错误恢复完成率。减少检查次数不能单独证明信任提升。
2. 走查首次使用、跨会话返回、偏好冲突、删除记忆、撤销授权和动作结果未知。每个场景写明输入、用户可见行为与通过条件。
3. 分开报告人工走查、已运行的产品测试和未验证能力。设计文案中的删除、撤销或跨设备承诺不能当作已实现功能。

## Output Format

按用户要求的深度交付；短评只给问题、影响和修正建议，完整方案包含：

1. 用户目标、协作周期、证据与假设。
2. 记忆契约：信息、用途、来源、范围、有效期、纠正 / 删除方式。
3. 动作授权表：授权边界、展示方式、结果核实与恢复。
4. 核心流程和状态：首次、返回、变更、暂停 / 取消、失败恢复。
5. 验收场景、收益指标及真实验证状态。

## Important Principles

- 信任依靠可靠结果和用户控制，不依靠拟人化、依赖诱导或增加使用时长。
- 最小可用记忆优先；简单偏好可直接存储，不为“关系模型”引入无需求的基础设施。
- 用户当前意图、数据边界和明确授权优先于历史推断。
- 设计建议不等于执行授权；不得擅自安装工具、保存用户数据或操作外部账户。

## Halt Conditions

- 记忆用途、访问范围或敏感数据授权不明时，暂停依赖这些决定的部分，提出一个聚焦问题；继续独立部分的设计。
- 动作超出有效授权或引入未授权的破坏性操作时，先完成可审阅预览，再请求缺少的授权；不得因关系成熟跳过。
- 缺少实际存储、删除或结果查询能力时，标注能力缺口并停止相关执行；设计中给出可行替代方案。

## Skill Verification

维护时使用 [压力场景](./evals/evals.json)：先记录无技能时的可能失败，再应用规则走查实际输出。出现越权、虚构记忆能力或范围扩张时收紧规则并重跑；场景文件本身不是测试通过证据。
