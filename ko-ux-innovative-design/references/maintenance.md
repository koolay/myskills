## Local adaptations

- Register `ux` and use `ko-ux-innovative-design`; descriptions follow repository trigger-only policy.
- Consolidate the operational rules into one skill. This reference is for maintenance, not a runtime dependency on GitHub.
- Preserve the unusual upstream boundaries deliberately: ten typography-only directions, no Round 1 rendering by the agent, no generated SVG, and human judgement before production.
- Replace "terminate the other nine" with stopping exploration while retaining files. Locking does not authorize deletion.
- Replace geographic foundry lists with requirement-led primary-source font research. Keep independent acquisition, Google Fonts exclusion, license checks, and provisional technical fallbacks.
- Honor existing authorization and host/project policy; routine reversible work does not need repeated permission. Source isolation does not prevent factual technical research.
- Do not automatically create a separate ledger or extra artifacts. The required capsule, context, and accepted style guide carry state.

## Validation guidance

Use `../evals/evals.json`. A baseline without this skill can be expected to open inspiration galleries, pre-label styles, render options, or infer production approval from praise; that expectation is not an observed result.

For an actual run, save the prompt and response, then check:

1. Sufficient subject and intent trigger action without an intake questionnaire.
2. First-round files contain only permitted text/color/space ingredients; capsules exist but are not exposed before reaction.
3. Praise is recorded as selection rather than lock; production waits for an explicit instruction.
4. Existing approved context bypasses exploration and preserves the requested artifact scope.
5. Source validation is not reported as visual or production verification.

Tests of decision boundaries may use textual replies. They do not prove the visual quality of generated designs, actual font rights, browser behavior, or accessibility. Record that limitation alongside observed results.

## Observed validation: 2026-09-30

Ran scenario 1 as one independent with-skill response and one baseline response. Both received the same Chinese prompt and the repository's coding guidelines; neither created design files. Responses and a generated review viewer were saved in a temporary evaluation workspace.

- **With skill, 5/5 textual assertions:** proposed A-J HTML directions using only typography/flat colors/space, hidden capsules, source-only checks, human first visual judgement, and an explicit production lock. It preserved the supplied copy and did not claim files existed.
- **Baseline, 2/5:** also used repair evidence and preserved the copy, but proposed three named illustrated/photographic directions with a recommendation before visual review. It did not define the ten-file/capsule contract or reserve first visual judgement explicitly.
- **Interpretation:** the measured difference is adherence to the skill's workflow, not a verdict that the baseline design approach is worse. Two assertions pass in both runs. One run per configuration cannot establish reliability.
- **Unverified:** scenarios 2-4, actual direction generation, visual quality, font licensing, browser/accessibility behavior, production exports, and human acceptance. Agent notifications supplied no token or timing metrics; none were invented.

Naming, frontmatter, required sections, new local links, eval JSON, retained MIT notice, and whitespace were checked. A pre-existing index link to `research/agent-guidelines-review.md` does not resolve; it is unrelated to this addition.
